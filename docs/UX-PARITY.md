# 顧客 UX の本番同等性（issue #11）

この文書は、顧客向け予約フローが本番運用の SaaS 版とユーザータスク単位でどこまで同等かを記録し、
既定構成では隠れる選択・アダプタ表面と、構成したときの導線を明文化します。

この文書は [`docs/PARITY.md`](PARITY.md) の両マトリクスから**導出されるタスク単位の証拠ビュー**です。
能力の現在ステータスの正本は
[ターゲットマトリクス](PARITY.md#production-parity-target-matrix)にあり、本文書の「先送り」行は
該当行の名前による参照です（ステータスやステージはここに複製しません）。ステータスが変わったときは
ターゲットマトリクスを更新し、本文書は参照先の変化に追従します。

## アダプタ挿入点（既定構成では描画されない）

既定のインストール（`default` のみ・外部プロバイダなし）では、次の表面を表示しません。
複数店舗や任意の LINE を設定したときだけ、その店舗・予約の範囲で表示します。
店舗の操作と API 境界は [multi-location guide](MULTI-LOCATION.md) を参照してください。

### 1. 店舗（location）選択

- **表示**: 予約可能な店舗が複数ある場合は、サービス選択より前に店舗を選びます。単一の
  `default` のみなら従来の表示を保ちます。選んだ店舗は確認・結果・保存済み予約にも残ります。
- **失敗時**: 明示した不明店舗は別の店舗へ自動切替せず、エラーを表示します。停止中の既知店舗でも
  保存済み予約の確認・取消は元の店舗の証明で続けられます。
- **検証対象**: `tests-browser/customer.spec.ts` の店舗選択・未知 URL・キーボードと、
  `tests-browser/multi-location.spec.ts` の実バックエンドでの予約・確認・保存済み証明・停止店舗の管理。
  320–1440 px の表示も確認します。

### 2. 本人確認（identity）アダプタ

- **既定**: 顧客アカウントは不要です。予約ごとの管理キーで状態確認・取消を行います。
- **任意 LINE**: LIFF は選んだ予約と店舗の通知リンクに使います。別店舗の予約を同じ LINE
  subject で自動的に結び付けたり、全店舗共通の顧客 ID を作ったりしません。
- **範囲外**: 全予約を横断する外部 ID ログインと連絡先による本人照合は未実装です。

### 3. 通知（notification）チャネル

- **既定**: 通知を約束しません。未構成の LINE、メール、SMS を結果画面に出しません。
- **任意 LINE**: 有効な店舗で顧客がその予約を明示的にリンクした場合だけ、確定した状態変更に
  対する通知を送ります。失敗しても予約状態は変わらず、保存済み予約ページが正本です。

## ユーザータスク別 同等性マトリクス

判定は 3 値です: **同等**（本番フローと同じ結果に同じ負担で到達できる）/ **同等以上**（OSS 側だけの
価値がある）/ **先送り**（アダプタ待ち。理由を明記）。根拠列は自動テストまたは文書の所在です。

| ユーザータスク | 判定 | 根拠 |
|---|---|---|
| サービス・日時を選び、3 ステップで予約を申請する | 同等 | `tests-browser/customer.spec.ts` の一気通貫予約（320–1440 px、キーボード到達、axe） |
| 連絡先入力の前に選択内容を確かめ、その場で直す | 同等 | サマリーカードと編集リンクの往復テスト（details step の要約・編集ジャンプ・反映） |
| 送信前に完成した内容を専用画面で最終確認する | 同等 | 確認パネル（`[data-confirmation-panel]`）の表示と隔離された主ボタンのテスト |
| 多数のサービスから絞り込んで選ぶ | 同等 | 9 件カタログのキーボード操作テスト（フィルタ→選択→チップ削除、概算合計、8 件以下は従来表示のまま） |
| 選択済みサービスの合計（時間・料金）を把握する | 同等 | 概算合計行のテスト。未掲載料金が混じる場合は合計を出さない（誤読防止） |
| 空き状況をその場で更新して選び直す | 同等 | 更新ボタンのテスト（選択済み時刻を保ったまま再描画） |
| 臨時のお知らせ（短縮営業など）に気づく | 同等 | `availabilityNotice` の表示・非表示テストと設定画面の往復テスト |
| 満枠・枠切れの理由を理解して復帰する | 同等 | 上限到達文言と stale-slot 文言のシェル内テスト（選択ステップへの復帰まで） |
| 同じ日の二重予約に気づいてから申請する | 同等（同一ブラウザ内） | 保存済み予約 ≤3 件の照会→警告→確認→完了のテスト。照会失敗は申請を妨げない |
| 端末をまたいだ二重予約に気づく | 先送り（全店舗共通の顧客 ID は対象外） | 照合は保存済み証明に限定。連絡先照合は列挙オラクル化するため不採用 |
| アカウントなしで予約を確認・取消する | 同等以上 | 管理キーによる無アカウント運用（外部 ID 不要は OSS 側の特性）。保存・取消・再読込のテスト |
| 管理キーの意味を理解して保管する | 同等 | 成功画面の一文説明・コピー・保存導線のテストと `bookings.html` の入口文 |
| 予約結果の通知を受け取る | 同等（LINE 構成・予約ごとの同意時） | 未構成では通知を約束しない。LINE のリンク・配送・失敗導線は `tests-browser/line.spec.ts` と adapter テストで確認する |
| 店舗を選ぶ | 同等（複数の予約可能店舗がある場合） | `tests-browser/customer.spec.ts` の選択・未知店舗と `tests-browser/multi-location.spec.ts` の実バックエンド予約・確認・保存済み証明・停止店舗管理で確認する。既定のみではセレクタを隠す |
| 外部 ID でログインする | 同等（LINE 構成・予約単位のリンク時） | LIFF ログインと管理キー証明によるリンクは `tests-browser/line.spec.ts` で確認する。全店舗共通の顧客アカウントにはならない |
